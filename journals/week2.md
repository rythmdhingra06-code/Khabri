## Week 2: Requirements Analysis and Technology Selection

Objectives
- List functional and non-functional requirements.
- Choose the tools and technologies.

Work Done
- Listed functional requirements: search news, filter by topic, view feed, subscribe to topics, read article.
- Listed system requirements: aggregation, de-duplication, processing, caching and categorisation.
- Listed non-functional requirements: fast response, reliability under API rate limits, usability on mobile and desktop.
- Explored news sources: RSS feeds and REST APIs.
- Selected the technical stack:
  - Language/framework: Python, Node.js, React (or Flask/FastAPI)
  - Database: PostgreSQL / MongoDB
  - Caching: Redis / local storage
  - Tools: Git, Postman, Docker, VS Code
  - Libraries: Beautiful Soup, Axios, NLTK/Spacy, Pandas
- Chose the iterative SDLC model, since the project has several modules that can be built and tested one at a time.

Challenges
- Choosing between SQL and NoSQL databases for article storage.
- Free news APIs have request limits.

Learnings
- Requirements must be written down before design, so that scope changes can be tracked.

Plan for Next Week
- Prepare the use case model and the system architecture.
